LoGoPlanner RGB-D low-latency two-machine commands
Last updated: 2026-03-19

Scenario
--------
1. These commands are for RGB-D capture machine -> GPU inference machine.
2. Primary path is HTTP fast:
   - POST /navigator_reset
   - POST /pointgoal_step_fast
3. Goal: compress ROS topics on the capture PC and send to the other machine; this is not the sentry_planner vision serial path.
4. By default you do not need:
   - ./start_robot.sh
   - ros2 launch rm_vision_bringup vision_bringup.launch.py
   - rm_serial_driver
5. If the server switches to a ZMQ bridge later, switch client to zmq mode.


0. Defaults
=============

GPU inference side
------------------
SERVER_URL=http://10.224.36.118:19999

Default ROS topics on capture machine
-------------------------------------
RGB             : /usb_cam_color/image_raw
Depth           : /camera/depth/image_raw
RGB camera_info : /usb_cam_color/camera_info
Depth info      : /camera/depth/camera_info

Default send parameters
-----------------------
transport       : http_fast
rgb/depth size  : 320x240
jpeg_quality    : 60
send_fps        : 5
queue size      : 1
policy          : latest-frame-only

=======================================

2.1 List relevant topics
------------------------
source /opt/ros/humble/setup.zsh
ros2 topic list | grep -E 'usb_cam_color|camera/depth|image_raw|camera_info'

2.2 Check RGB is publishing
---------------------------

2.3 Check depth is publishing
-----------------------------
source /opt/ros/humble/setup.zsh

2.4 One-shot RGB intrinsics
---------------------------

ros2 topic echo /usb_cam_color/camera_info --once

2.5 One-shot depth intrinsics
-----------------------------
source /opt/ros/humble/setup.zsh
ros2 topic echo /camera/depth/camera_info --once

If your real topic names differ
---------------------------------
Replace these four in the run command:
--rgb-topic
--depth-topic
--rgb-info-topic
--depth-info-topic

3.3 Transport latency only (skip ROS / depth for now)
------------------------------------------------------
Run the synthetic benchmark:

cd /home/nyu/sentry_planner/logo_low_latency_client
source .venv/bin/activate
python3 -m client.benchmark_transport \
  --transport http_fast \
  --server-url http://10.224.36.118:19999 \
  --iterations 20 \
  --warmup 3 \
  --send-fps 5 \
  --show-stats

This will:
1. Generate 320x240 RGB JPEG locally
2. Generate 320x240 depth PNG locally
3. Call /navigator_reset
4. Call /pointgoal_step_fast repeatedly
5. Print request_total_ms / end_to_end_ms / server_total_ms

3.4 Include re-encoding in the measurement
------------------------------------------
cd /home/nyu/sentry_planner/logo_low_latency_client
source .venv/bin/activate
python3 -m client.benchmark_transport \
  --transport http_fast \
  --server-url http://10.224.36.118:19999 \
  --iterations 20 \
  --warmup 3 \
  --send-fps 5 \
  --reencode-each-frame \
  --show-stats

Notes
-----
1. Without --reencode-each-frame: closer to “transport only”.
2. With --reencode-each-frame: closer to end-to-end capture+compress+send.


4. Run HTTP fast client on capture machine
==========================================

4.1 Standard command
--------------------
source /opt/ros/humble/setup.zsh
cd /home/nyu/sentry_planner/logo_low_latency_client
source .venv/bin/activate

python3 -m client.main \
  --transport http_fast \
  --server-url http://10.224.36.118:19999 \
  --goal-x 3.0 \
  --goal-y 0.5 \
  --rgb-topic /usb_cam_color/image_raw \
  --depth-topic /camera/depth/image_raw \
  --rgb-info-topic /usb_cam_color/camera_info \
  --depth-info-topic /camera/depth/camera_info \
  --rgb-width 320 \
  --rgb-height 240 \
  --depth-width 320 \
  --depth-height 240 \
  --jpeg-quality 60 \
  --png-compression 1 \
  --request-timeout 5.0 \
  --send-fps 5 \
  --show-stats \
  --save-json \
  --latest-json results/latest_result.json

4.2 If your topic names differ

4.3 If depth is float (meters)
------------------------------
Default converts meters to uint16 millimeters:
--depth-float-scale 1000

Example:
python3 -m client.main \
  --transport http_fast \
  --server-url http://10.224.36.118:19999 \
  --rgb-topic /usb_cam_color/image_raw \
  --depth-topic /camera/depth/image_raw \
  --rgb-info-topic /usb_cam_color/camera_info \
  --depth-info-topic /camera/depth/camera_info \
  --depth-float-scale 1000 \
  --show-stats


5. Expected log after startup
=============================

In normal operation you should see something like:
--------------------------------------------------
ROS capture node subscribed ...
ROS capture thread started.
Sender loop started ...
First paired RGB-D frame captured ...
navigator_reset ok ...
frame=... | transport=http_fast | end_to_end=... | server_total=...

If it stops after the first three lines
-----------------------------------------
Usually:
1. RGB / depth / camera_info not all available.
2. RGB and depth timestamps too far apart (not paired).
3. Wrong topic names.

7. How to tell if latency improved
==================================

7.1 From client log
-------------------
Watch:
capture_ts_ms
encode_start_ts_ms
send_start_ts_ms
recv_ts_ms
resize_ms
encode_ms
request_total_ms
roundtrip_ms
end_to_end_ms

7.2 If server returns timing
----------------------------
Also:
server_parse_ms
server_decode_ms
server_inference_ms
server_total_ms

7.3 Heuristic
-------------
1. LoGoPlanner inference is roughly 0.55s–0.65s.
2. Focus on pushing down request_total_ms and end_to_end_ms.
3. If both drop vs old raw upload / multipart, the path is better.

8.3 If capture machine cannot reach server
------------------------------------------
Check:
1. Firewall
2. Mutual ping
3. Server binds 0.0.0.0:19999 not 127.0.0.1:19999
