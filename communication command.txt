The “current bridge output” below is an example; after USB re-plug device names change — use what your bridge prints.
-----------------------
MCU serial : /dev/ttyACM0   # example: may be ttyACM1, etc.
Vision PTY : /dev/pts/2
Radar PTY  : /dev/pts/3

Notes
-----
1. Only `sentry_bridge.py` may use the real USB port; do not hardcode names — use auto port when starting the bridge (see §1.2).
2. Vision uses Vision PTY; radar/navigation uses Radar PTY (or stable symlink /tmp/nyush-rm-sentry-radar).
3. After each bridge restart, /dev/pts/N may change; always use the latest bridge printout.
4. Jack up the robot before one-shot / keyboard tests.
5. Default debug mode is “vx/vy only”: Nav2 `wz` is ignored.

- `AUTOAIM_MODE=scan` — scan only, no vision takeover

- `AUTO_START_SERIAL_SENDER=0` — disable auto sender
- `AUTOAIM_SCAN_YAW_RATE_DEG_S=120.0`
- `AUTOAIM_SEARCH_PITCH_DEG=-6.0`

6. Quick troubleshooting
=========================

6.1 Bridge will not start
-------------------------
lsof /dev/ttyACM0

6.2 serial_sender silent
------------------------
It must use /dev/pts/3, not /dev/ttyACM0, and listen on /cmd_vel_chassis_bt

6.3 Vision silent
-----------------
`sentry.yaml` com_port should be /dev/pts/2 (example)

6.3.1 just says missing recipe
------------------------------
Check cwd:

- `just logger` / `just logger-cli` → `nyush-rm-control`
- `just test detect --web --send` → `nyush-rm-vision`

6.4 Behavior tree not moving
----------------------------
`bt_comm_adapter.py` must run; check /game_status /robot_status /all_robot_hp /detector/armors /cmd_vel_chassis_bt

6.5 PTY numbers changed after bridge restart
--------------------------------------------
Replace every /dev/pts/2 and /dev/pts/3 with the new bridge printout

6.6 Nav2 RViz did not open
--------------------------
`start_robot.sh` defaults `ENABLE_RVIZ=0` for hardware/headless.

To auto-start RViz:
ENABLE_RVIZ=1 START_SERIAL_SENDER=1 RADAR_PTY=/tmp/nyush-rm-sentry-radar ./start_robot.sh

6.7 Docs still show /dev/ttyACM0
--------------------------------
With the bridge, neither serial_sender nor vision should open /dev/ttyACM0 directly

6.8 Referee topics on the bridge path
-------------------------------------
Path:
referee system -> C-board huart6 -> MCU ST -> sentry_bridge.py -> Radar PTY -> serial_sender.py --ros2 -> /game_status + /robot_status

Hardware check:
source /opt/ros/humble/setup.zsh
ros2 topic echo /game_status --once
ros2 topic echo /robot_status --once
ros2 topic hz /game_status
ros2 topic hz /robot_status

Notes:
- MCU must run current sentry firmware
- Use repo `serial_sender.py`
- `bt_hotkey_debug.py` overwrites these two topics
